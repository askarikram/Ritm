# Ритм

Личный финансовый план с отдельными аккаунтами.
Приложение: https://ritm-r9m8.onrender.com

Node.js 24 и PostgreSQL 17. Сервер и API находятся в server.js, интерфейс — в public/index.html.
Шрифт Golos Text поставляется через @fontsource-variable/golos-text и отдаётся с домена приложения.
Исходная серверная версия: https://docs.google.com/document/d/1INeIP3YUElh3jfcVTkHIW5XqXuc7k4Eczm3BgOFrTAI/edit

## Запуск

npm install
npm run check
npm start

DATABASE_URL хранится в переменной окружения. NODE_ENV=production.
Render автоматически задаёт PORT и RENDER_EXTERNAL_URL. APP_ORIGIN нужен для собственного HTTPS-домена.
Размещение: Render Free и Neon Free, Frankfurt. Постоянный диск не используется.

## Пожелание дня и оформление

Под заголовком главной страницы находится компактная карточка пожелания дня.
До нажатия текст не передаётся браузеру; после открытия он доступен до полуночи.
Состояние хранится отдельно от финансового плана и сохраняется при повторном входе и на другом устройстве.
Часовой пояс аккаунта определяется при первом открытии по устройству и далее остаётся одинаковым для всех его устройств.
GET /api/wish возвращает состояние, POST /api/wish открывает только пожелание текущего дня.
Оба маршрута используют владельца серверной сессии; открытие требует Origin и X-Ritm-User.

daily-wishes.mjs содержит 150 коротких фраз: пять разных наборов по 30 дней.
Первым пяти аккаунтам, открывшим пожелание, назначаются разные наборы.
После 30 дней цикл повторяется; новые аккаунты сверх пяти используют наименее занятый набор.
Пожелания, дата смены суток, работа пяти аккаунтов и сохранность финансового плана проверяются в CI.

Интерфейс использует светлую зелёную палитру, Golos Text, единый набор линейных иконок
и горизонтальную навигацию на компьютере. На телефоне поступления и платежи отображаются карточками
с названием на всю ширину. Плавающая нижняя панель содержит пять основных разделов; профиль и настройки доступны через кнопку аккаунта в заголовке.

В поступлениях и платежах итоговая плановая сумма складывается из оставшихся записей основного списка.
После «Получено» или «Оплачено» запись исчезает из списка и остаётся в истории; итог уменьшается.
Отмена отметки возвращает запись текущего цикла в список и восстанавливает баланс.
Для ежемесячных записей первое число открывает новый цикл с исходным днём платежа:
31 января → 28/29 февраля → 31 марта. Оплаченные записи скрыты до следующего месяца.
Неоплаченные ежемесячные даты прошлых месяцев не переносятся в новый цикл.
Разовые неподтверждённые записи остаются в списке; подтверждённые больше не возвращаются.
Прошлые неподтверждённые недельные и годовые даты доступны в отдельном сворачиваемом блоке.
В истории можно настроить повторение, сохранив уже подтверждённые операции.
Списки обновляются в полночь по дате устройства и при возвращении на вкладку.

Внизу главной находится сводка полного календарного месяца с названием месяца и года, без графика:
доходы, расходы, остаток и взносы на цели. Учитываются все даты расписаний от первого до последнего числа,
включая подтверждённые операции; фактическая сумма или отметка не заменяют введённую плановую сумму.
Разовые траты из действия «Расход» также являются записями плана и учитываются один раз.
Повседневные расходы можно включить отдельной галочкой: сумма за день умножается на число дней месяца.
В сводке показаны только суммы и галочка; формула, разбивка расходов и пояснение периода убраны из интерфейса.

Остаток = деньги на начало месяца + доходы − расходы − плановые взносы на цели.
Сумму на начало можно задать в самой сводке; редактирование не меняет текущий баланс.
До задания сумма восстанавливается из текущего баланса обратным учётом фактической истории.
При первом подтверждении операции начальная сумма текущего месяца фиксируется, чтобы подтверждения
и операции задним числом не меняли основу бюджета. Пользователь может исправить её вручную.
Плановые взносы целей фиксируются перед фактическим резервированием; подтверждение, частичный взнос
и завершение цели сохраняют сумму текущего месяца. Изменение настроек цели обновляет её план.

В версии плана 1 используются необязательные поля monthBalances (суммы на начало по YYYY-MM),
monthlyIncludeDaily (включение повседневного бюджета) и goal.monthPlans (плановые взносы по YYYY-MM).
Сервер и браузер проверяют эти поля; существующие файлы без них остаются совместимыми.
Суммы месячной сводки складываются точно с BigInt.
Прогноз в календаре по-прежнему охватывает текущий и следующий календарные месяцы.
Итог списка учитывает каждое активное расписание один раз; прогноз учитывает даты событий.
Для точного суммирования используется целочисленная арифметика минимальных единиц валюты.
Во всём интерфейсе и пожеланиях используется написание «теңге».

## Аккаунты

При регистрации пароль вводится дважды; совпадение проверяют браузер и сервер.
Кнопки с глазом показывают и скрывают пароль.
В Настройках → Профиль можно изменить имя и пароль.
Смена пароля требует текущий пароль и подтверждение нового. Другие сессии этого аккаунта завершаются,
текущая получает новый токен. Финансовый план остаётся прежним.

PATCH /api/profile — изменение имени.
POST /api/password — смена пароля.
Все изменения требуют действующую сессию, верный Origin и X-Ritm-User.
Планы выбираются по UUID пользователя из серверной сессии. Сохранение проверяет revision.

## Проверки

npm run check проверяет синтаксис Node.js и браузерного скрипта, а также файлы шрифта.
GitHub Actions запускает PostgreSQL 17 с TLS в одноразовом контейнере, HTTP-проверки аккаунтов и браузерные
проверки Chromium/WebKit на ширинах 320, 360, 390, 414, 768 и 1440 пикселей. Производственная база в CI не используется.
Скриншоты в логах проверок содержат только тестовые данные.
Дополнительно проверяются подтверждение и отмена, переход на первое число без перезагрузки,
история прошлых месяцев, короткий февраль, границы прогнозов и скрытие новых итогов.
Месячная сводка проверяется до и после подтверждений, при отличающейся фактической сумме,
частичном взносе на цель, изменении денег на первое число и переключении учёта повседневных расходов.

Для проверки опубликованной версии установить RITM_VERIFY_DEPLOY=1.
Стартовый скрипт ждёт выхода нужного коммита на публичный HTTPS-адрес и проверяет два тестовых аккаунта,
подтверждение пароля, изменения профиля, смену пароля, изоляцию и сохранность планов.
Тест удаляет только созданные им аккаунты. Пароли и cookie не выводятся.
После подтверждения RITM_ISOLATION_PASS вернуть RITM_VERIFY_DEPLOY=0.

Render Free засыпает после простоя: https://render.com/docs/free

## Устанавливаемый сайт

Опубликованный HTTPS-сайт содержит manifest.webmanifest, Service Worker и собственные иконки.
Режим standalone работает после установки через браузер. iPhone: Safari → Поделиться → На экран Домой.
Android: Chrome → Установить приложение. Подсказка доступна на странице входа и в настройках.
Публичные страницы /help и /privacy объясняют использование и хранение данных; /robots.txt и /sitemap.xml генерируются с APP_ORIGIN.

Service Worker кеширует только общий HTML, шрифты, манифест и иконки.
Ответы /api/, пользовательские планы и коды в Cache Storage не попадают.
Вход и синхронизация требуют интернета. Изменения уже открытого плана остаются в памяти до сохранения;
после возвращения связи сохранение повторяется. Перед закрытием страницы можно скачать JSON.
Это не полноценный режим редактирования без интернета и не автоматическая резервная копия базы.

Новый Service Worker ждёт явного нажатия «Обновить». Обновление блокируется при несохранённом плане,
выполнении запросов, открытом диалоге или незавершённом вводе пароля.
Старые кеши Ритма удаляются при активации новой версии. Посторонние кеши не удаляются.
PNG-иконки 192/512/180 генерируются из одного знака в app-icons.mjs, без внешних сервисов.

## Резервный код и удаление аккаунта

Регистрация выдаёт случайный код восстановления с 128 битами энтропии.
В PostgreSQL хранится только SHA-256 кода в ritm_recovery_codes.
Код показывается в отдельном диалоге и скачивается пользователем; после закрытия удаляется из DOM.
GET /api/me сообщает только recoveryEnabled, никогда не возвращая секрет.

POST /api/recovery-code требует действующую сессию, текущий пароль, Origin и X-Ritm-User.
POST /api/recover требует логин, код, новый пароль и подтверждение.
Восстановление атомарно меняет пароль, завершает все старые сеансы, выдаёт новый код и новый сеанс;
финансовый план и revision не меняются. Одновременное использование одного кода проходит только один раз.
Старый код после восстановления или замены не действует. Попытки ограничиваются по аккаунту и адресу.
Для старых аккаунтов код нужно создать в Настройках до потери пароля. Почтового восстановления нет.

DELETE /api/account требует текущий пароль и строку УДАЛИТЬ, действующую сессию, Origin и X-Ritm-User.
Удаление каскадно убирает план, сеансы, пожелания и код из рабочей базы.
Сроки хранения инфраструктурных журналов и резервных копий определяют Render и Neon.

## Следующий этап размещения

Текущий сайт и установка работают на существующем HTTPS-адресе.
Для собственного домена владелец должен предоставить зарегистрированный домен и доступ к DNS;
после подключения нужно задать APP_ORIGIN и проверять вход, cookie, manifest и сертификат на новом адресе.
При смене домена пользователи устанавливают приложение с нового адреса.
Render Free может засыпать после простоя. Переход на тариф без засыпания требует выбора и оплаты тарифа владельцем.
Встроенный бесплатный history window Neon остаётся 6 часов. Отдельный workflow backup-daily.yml сохраняет полные зашифрованные копии в GitHub Actions на 30 дней; для его включения требуется RITM_BACKUP_KEY в Render.
Пользовательский экспорт JSON уже доступен, но не заменяет копирование всей базы.

CI дополнительно проверяет страницы сайта, реальные PNG, восстановление, однократность кода при конкуренции,
отзыв сеансов, удаление аккаунта и сохранность другого аккаунта. В Chromium/WebKit проверяются установка,
работа Service Worker, отсутствие личных данных в кеше, экспорт при потере связи и сохранение после подключения.

Запуск из кеша в WebKit проверяется остановкой и перезапуском одноразового тестового HTTP-сервера: offline-эмуляция Playwright отклоняет даже локальный ответ Service Worker (microsoft/playwright#42775). Chromium проверяется с browserContext.setOffline. Оба сценария требуют ответ 200 из Service Worker и отсутствие открытого личного плана при недоступной сети. Рабочий сервис не останавливается.

## Скрытие финансовых сумм

Кнопка с глазом в заголовке рядом с аккаунтом и выходом скрывает суммы во всех разделах.
Суммы, включая месячную сводку, заменяются четырьмя точками; проценты накоплений скрываются. Повторное нажатие возвращает их.
В режиме скрытия денежные поля в диалогах отображаются как password-поля с цифровой клавиатурой.
Даты, названия и навигация остаются читаемыми. План, расчёты и файлы экспорта не изменяются.
На устройстве в localStorage сохраняется только флаг вида для конкретного логина, без финансовых значений.
Состояние загружается до отображения плана, сохраняется после обновления страницы и отделено от других аккаунтов.
Это режим отображения; он не меняет авторизацию и не шифрует данные, уже загруженные в браузер.


## Архив месяцев и напоминания

«Архив» открывается из бюджета месяца. Доступны завершённые месяцы начиная с января 2026 года. Для каждого месяца можно отдельно указать валюту, сумму на начало, доходы, расходы и взносы на цели; остаток считается автоматически. Эти записи не меняют текущий план, баланс и историю операций. Не заполненные месяцы остаются пустыми. Последние сохранённые показатели текущего месяца фиксируются при входе и при сохранении плана, а после смены месяца становятся доступны в архиве. Исправленный вручную месяц защищён от автоматической перезаписи.

Колокольчик открывает ближайшие платежи и настройки двух каналов: внутри Ритма и Web Push на устройство. Поддерживаются день платежа, за один или три дня, местное время и отдельная настройка показа сумм. Уведомления на конкретном устройстве включаются только после разрешения браузера. На iPhone требуется установка сайта на экран «Домой» и iOS 16.4 или новее. На компьютере уведомления приходят через поддерживающий Web Push браузер.

Фоновая доставка работает через бесплатный GitHub Actions workflow reminder-delivery.yml каждые 15 минут. Расписание GitHub может задерживаться: время означает «после выбранного времени», точность до минуты не гарантируется. Планировщик авторизуется короткоживущей OIDC-подписью GitHub, привязанной к этому репозиторию и workflow в main; секретов в репозитории нет. Сервер отправляет настоящие зашифрованные Web Push сообщения. VAPID-ключи создаются один раз и хранятся в PostgreSQL. Подписка привязана к сессии и удаляется при выходе, восстановлении доступа или удалении аккаунта. Оплаченные события исключены; отправки одного события в одном окне не дублируются.

Service Worker хранит для уведомлений только непрозрачный идентификатор владельца и флаг скрытия сумм. Если включён глазок, суммы скрыты и в уведомлениях, даже при включённой настройке показа сумм. Финансовые API и планы не попадают в Cache Storage. Телеграм и почта не используются.

Проверки scripts/test-features.mjs включают изоляцию архива, конфликты версий, независимость текущего плана, OIDC, реальную зашифрованную доставку Web Push на одноразовый HTTPS-приёмник, защиту от повторной отправки и отзыв подписки при выходе. scripts/test-feature-ui.mjs проверяет архив и напоминания в Chromium и WebKit на 320, 390 и 1440 пикселях.


## Личный планировщик

Раздел «Личное» заменяет пункт «Цели» в основном меню. В нём находятся «Мой день», «Мои привычки» и вход «Накопить деньги». Старый адрес #goals продолжает открывать финансовые цели внутри «Личного»; все суммы и режимы накопления сохраняются.

Личные данные хранятся отдельно в ritm_personal и не входят в финансовый JSON, его экспорт, импорт, очистку, расчёты и архив. Задачи имеют название, дату, необязательное время и отметку выполнения. Перенос меняет дату и время существующей задачи. Выполненные задачи остаются видимыми и зачёркнутыми; отметку можно снять. Привычки повторяются ежедневно с выбранной даты либо действуют один день. Выполнение хранится отдельно для каждой даты. Будущие дни доступны для просмотра; привычку нельзя заранее отметить за будущий день. Привычки не переносятся.

Выбор дня поддерживает предыдущий и следующий день, календарь и возврат к сегодня. На главной показываются по одной ближайшей невыполненной задаче и привычке, обновляясь по местному времени аккаунта. После выполнения карточка переходит к следующему делу. Меню телефона состоит из пяти отдельных округлённых плиток; выбранная плитка выделена зелёным, подписи сохраняют положение.

API GET/POST /api/personal привязан к сессии, X-Ritm-User и проверке Origin. Изменения используют отдельную версию и транзакционную блокировку для защиты от одновременной перезаписи. Ошибка сохранения оставляет введённые поля в редакторе. Выход и смена аккаунта очищают личные данные из интерфейса. Удаление аккаунта удаляет личный раздел.

Задачи и привычки с указанным временем используют уже включённый на устройстве канал напоминаний. Фоновый планировщик каждые 15 минут отправляет напоминание о текущем невыполненном деле, когда его время наступило. На экране блокировки названия личных дел скрыты; переход открывает «Личное». Оплаченные платежи, выполненные дела и перенесённые задачи повторно не отправляются. Пустое время не создаёт push-напоминание. Книги пока доступны как привычка чтения; библиотека не добавлялась.

Проверки scripts/test-personal.mjs и scripts/test-personal-ui.mjs покрывают изоляцию аккаунтов, сохранность финансов, произвольный перенос, ежедневное выполнение и смену дня, фоновые уведомления, конфликт версий и работу интерфейса в Chromium/WebKit на 320–1440 пикселях.


## Защита и полные резервные копии

Пароли новых аккаунтов и новые пароли при смене/восстановлении: 12–128 символов, с пробелами, Unicode и специальными знаками. Распространённые и односимвольные повторяющиеся пароли отклоняются. Старые пароли от 8 символов продолжают работать при входе. Не более двух затратных scrypt-операций одновременно. Бюджеты попыток атомарно хранятся в ritm_rate_limits и сохраняются после перезапуска. Адрес прокси не считается достоверным адресом отдельного посетителя: дополнительно действует независимый лимит конкретного логина.

Повторяющиеся даты сразу переходят к запрошенному месяцу/неделе. Возраст записи не увеличивает время расчёта сводки. Сервер и браузер используют одну и ту же реализацию.

package-lock.json фиксирует транзитивные версии. CI устанавливает их через npm ci. Существующий сервис Render использует npm install с этим lock-файлом; новый сервис из render.yaml использует npm ci. Скрипты установки зависимостей на Render отключены через npm_config_ignore_scripts. npm audit проверяет production-зависимости в CI и при сборке Render; любой известный уровень уязвимости блокирует проверку. Отдельный workflow повторяет аудит еженедельно, Dependabot готовит обновления. GitHub Actions закреплены за проверенными commit SHA.

Полная копия включает аккаунты, хеши паролей и кодов восстановления, финансовые планы, архив, личные задачи и привычки, пожелания, настройки напоминаний и VAPID-ключи. Действующие сессии и подписки устройств не восстанавливаются: после восстановления пользователи входят и включают устройство заново.

Для ежедневного копирования задайте в Render секрет RITM_BACKUP_KEY: 32 случайных байта в hexadecimal (64 символа). Генерация на доверенном компьютере: node -p "require('node:crypto').randomBytes(32).toString('hex')". Сохраните отдельную копию ключа в менеджере паролей владельца. Не меняйте его без сохранения старого ключа: предыдущие копии требуют предыдущий ключ. Ключ не попадает в репозиторий, артефакты и логи. Не храните ключ рядом с копией. Без ключа сервер явно отклоняет резервное копирование с 503; workflow завершается ошибкой, а не сообщает ложный успех.

backup-daily.yml запускается ежедневно в 02:17 UTC (07:17 Asia/Almaty), а также вручную и после изменения реализации копирования. Расписание GitHub может задерживаться. Workflow получает короткоживущий GitHub OIDC-токен для строго заданного workflow в main. Напоминания не могут использовать свою подпись для чтения копии. Сервер делает согласованный REPEATABLE READ snapshot, шифрует gzip-JSON AES-256-GCM и проверяет расшифровку до выдачи. Артефакт содержит только шифротекст; хранится 30 дней вне Neon. Копии старше срока удаляются GitHub.

Восстановление: создайте НОВУЮ пустую базу, запустите эту версию Ритма для создания таблиц, остановите её и выполните npm run restore:backup -- path/to/encrypted-backup.json с RITM_RESTORE_URL новой базы и RITM_BACKUP_KEY. Не используйте URL работающей базы. Заполненная база отклоняется; восстановление идёт одной транзакцией и проверяет количество записей. CI проверяет точное восстановление содержимого всех постоянных таблиц в одноразовую схему, неверный ключ, подмену файла и отказ перезаписи существующих записей.

Шифрование резервных файлов не является сквозным шифрованием интерфейса: сервер приложения всё ещё обрабатывает введённые данные. Neon также шифрует данные на носителях на уровне своей инфраструктуры. Режим «глазок» остаётся настройкой отображения.


## Основа Premium и аккаунт разработчика

ritm_memberships хранит доступ по неизменному user_id. Существующий аккаунт askar получает Premium без срока окончания и признак developer при запуске сервера. Этот логин зарезервирован: его нельзя заново занять публичной регистрацией после удаления аккаунта. Это не даёт доступа к чужим финансовым данным. GET /api/membership и user.membership в ответах входа/профиля сообщают права только владельцу текущей сессии; клиент не может назначить их самостоятельно.

Разделение интерфейса на базовый и Premium, страница оплаты и обработка переводов находятся на стадии макета. Права в интерфейсе для остальных пользователей пока не ограничиваются. Цена и реквизиты не опубликованы как предложение оплаты. Подтверждение «Я оплатил» в будущей реализации создаёт только заявку; Premium включается после проверки перевода разработчиком.

Резервные копии включают ritm_memberships. Копии прежней версии с восемью постоянными таблицами принимаются с пустой таблицей прав. При восстановлении старой копии аккаунт askar снова получает пожизненный доступ при запуске сервера.

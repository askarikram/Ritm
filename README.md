# Ритм

Личный финансовый план с отдельными аккаунтами.
Приложение: https://ritm-r9m8.onrender.com

Node.js 24 и PostgreSQL 17. Сервер и API находятся в server.js, интерфейс — в public/index.html.
Шрифт Golos Text поставляется через @fontsource-variable/golos-text и отдаётся с домена приложения.
Исходная серверная версия: https://docs.google.com/document/d/1INeIP3YUElh3jfcVTkHIW5XqXuc7k4Eczm3BgOFrTAI/edit

## Запуск

npm install
npm run check
npm start

DATABASE_URL хранится в переменной окружения. NODE_ENV=production.
Render автоматически задаёт PORT и RENDER_EXTERNAL_URL. APP_ORIGIN нужен для собственного HTTPS-домена.
Размещение: Render Free и Neon Free, Frankfurt. Постоянный диск не используется.

## Пожелание дня и оформление

Под заголовком главной страницы находится компактная карточка пожелания дня.
До нажатия текст не передаётся браузеру; после открытия он доступен до полуночи.
Состояние хранится отдельно от финансового плана и сохраняется при повторном входе и на другом устройстве.
Часовой пояс аккаунта определяется при первом открытии по устройству и далее остаётся одинаковым для всех его устройств.
GET /api/wish возвращает состояние, POST /api/wish открывает только пожелание текущего дня.
Оба маршрута используют владельца серверной сессии; открытие требует Origin и X-Ritm-User.

daily-wishes.mjs содержит 150 коротких фраз: пять разных наборов по 30 дней.
Первым пяти аккаунтам, открывшим пожелание, назначаются разные наборы.
После 30 дней цикл повторяется; новые аккаунты сверх пяти используют наименее занятый набор.
Пожелания, дата смены суток, работа пяти аккаунтов и сохранность финансового плана проверяются в CI.

Интерфейс использует светлую зелёную палитру, Golos Text, единый набор линейных иконок
и горизонтальную навигацию на компьютере. На телефоне поступления и платежи отображаются карточками
с названием на всю ширину. Плавающая нижняя панель содержит пять основных разделов; профиль и настройки доступны через кнопку аккаунта в заголовке.

В поступлениях и платежах итоговая плановая сумма складывается из оставшихся записей основного списка.
После «Получено» или «Оплачено» запись исчезает из списка и остаётся в истории; итог уменьшается.
Отмена отметки возвращает запись текущего цикла в список и восстанавливает баланс.
Для ежемесячных записей первое число открывает новый цикл с исходным днём платежа:
31 января → 28/29 февраля → 31 марта. Оплаченные записи скрыты до следующего месяца.
Неоплаченные ежемесячные даты прошлых месяцев не переносятся в новый цикл.
Разовые неподтверждённые записи остаются в списке; подтверждённые больше не возвращаются.
Прошлые неподтверждённые недельные и годовые даты доступны в отдельном сворачиваемом блоке.
В истории можно настроить повторение, сохранив уже подтверждённые операции.
Списки обновляются в полночь по дате устройства и при возвращении на вкладку.

Главная показывает план до последнего числа текущего месяца и ожидаемый остаток на счетах.
Отдельно показан доступный остаток с учётом денег на цели; переводы на цели не уменьшают общую сумму на счетах.
Прогноз в календаре охватывает текущий и следующий календарные месяцы.
Итог списка учитывает каждое активное расписание один раз; прогноз учитывает даты событий.
Для точного суммирования используется целочисленная арифметика минимальных единиц валюты.
Во всём интерфейсе и пожеланиях используется написание «теңге».

## Аккаунты

При регистрации пароль вводится дважды; совпадение проверяют браузер и сервер.
Кнопки с глазом показывают и скрывают пароль.
В Настройках → Профиль можно изменить имя и пароль.
Смена пароля требует текущий пароль и подтверждение нового. Другие сессии этого аккаунта завершаются,
текущая получает новый токен. Финансовый план остаётся прежним.

PATCH /api/profile — изменение имени.
POST /api/password — смена пароля.
Все изменения требуют действующую сессию, верный Origin и X-Ritm-User.
Планы выбираются по UUID пользователя из серверной сессии. Сохранение проверяет revision.

## Проверки

npm run check проверяет синтаксис Node.js и браузерного скрипта, а также файлы шрифта.
GitHub Actions запускает PostgreSQL 17 с TLS в одноразовом контейнере, HTTP-проверки аккаунтов и браузерные
проверки Chromium/WebKit на ширинах 320, 360, 390, 414, 768 и 1440 пикселей. Производственная база в CI не используется.
Скриншоты в логах проверок содержат только тестовые данные.
Дополнительно проверяются подтверждение и отмена, переход на первое число без перезагрузки,
история прошлых месяцев, короткий февраль, границы прогнозов и скрытие новых итогов.

Для проверки опубликованной версии установить RITM_VERIFY_DEPLOY=1.
Стартовый скрипт ждёт выхода нужного коммита на публичный HTTPS-адрес и проверяет два тестовых аккаунта,
подтверждение пароля, изменения профиля, смену пароля, изоляцию и сохранность планов.
Тест удаляет только созданные им аккаунты. Пароли и cookie не выводятся.
После подтверждения RITM_ISOLATION_PASS вернуть RITM_VERIFY_DEPLOY=0.

Render Free засыпает после простоя: https://render.com/docs/free

## Устанавливаемый сайт

Опубликованный HTTPS-сайт содержит manifest.webmanifest, Service Worker и собственные иконки.
Режим standalone работает после установки через браузер. iPhone: Safari → Поделиться → На экран Домой.
Android: Chrome → Установить приложение. Подсказка доступна на странице входа и в настройках.
Публичные страницы /help и /privacy объясняют использование и хранение данных; /robots.txt и /sitemap.xml генерируются с APP_ORIGIN.

Service Worker кеширует только общий HTML, шрифты, манифест и иконки.
Ответы /api/, пользовательские планы и коды в Cache Storage не попадают.
Вход и синхронизация требуют интернета. Изменения уже открытого плана остаются в памяти до сохранения;
после возвращения связи сохранение повторяется. Перед закрытием страницы можно скачать JSON.
Это не полноценный режим редактирования без интернета и не автоматическая резервная копия базы.

Новый Service Worker ждёт явного нажатия «Обновить». Обновление блокируется при несохранённом плане,
выполнении запросов, открытом диалоге или незавершённом вводе пароля.
Старые кеши Ритма удаляются при активации новой версии. Посторонние кеши не удаляются.
PNG-иконки 192/512/180 генерируются из одного знака в app-icons.mjs, без внешних сервисов.

## Резервный код и удаление аккаунта

Регистрация выдаёт случайный код восстановления с 128 битами энтропии.
В PostgreSQL хранится только SHA-256 кода в ritm_recovery_codes.
Код показывается в отдельном диалоге и скачивается пользователем; после закрытия удаляется из DOM.
GET /api/me сообщает только recoveryEnabled, никогда не возвращая секрет.

POST /api/recovery-code требует действующую сессию, текущий пароль, Origin и X-Ritm-User.
POST /api/recover требует логин, код, новый пароль и подтверждение.
Восстановление атомарно меняет пароль, завершает все старые сеансы, выдаёт новый код и новый сеанс;
финансовый план и revision не меняются. Одновременное использование одного кода проходит только один раз.
Старый код после восстановления или замены не действует. Попытки ограничиваются по аккаунту и адресу.
Для старых аккаунтов код нужно создать в Настройках до потери пароля. Почтового восстановления нет.

DELETE /api/account требует текущий пароль и строку УДАЛИТЬ, действующую сессию, Origin и X-Ritm-User.
Удаление каскадно убирает план, сеансы, пожелания и код из рабочей базы.
Сроки хранения инфраструктурных журналов и резервных копий определяют Render и Neon.

## Следующий этап размещения

Текущий сайт и установка работают на существующем HTTPS-адресе.
Для собственного домена владелец должен предоставить зарегистрированный домен и доступ к DNS;
после подключения нужно задать APP_ORIGIN и проверять вход, cookie, manifest и сертификат на новом адресе.
При смене домена пользователи устанавливают приложение с нового адреса.
Render Free может засыпать после простоя. Переход на тариф без засыпания требует выбора и оплаты тарифа владельцем.
Автоматические копии базы и сроки восстановления необходимо настроить в аккаунте Neon отдельно.
Пользовательский экспорт JSON уже доступен, но не заменяет копирование всей базы.

CI дополнительно проверяет страницы сайта, реальные PNG, восстановление, однократность кода при конкуренции,
отзыв сеансов, удаление аккаунта и сохранность другого аккаунта. В Chromium/WebKit проверяются установка,
работа Service Worker, отсутствие личных данных в кеше, экспорт при потере связи и сохранение после подключения.

Запуск из кеша в WebKit проверяется остановкой и перезапуском одноразового тестового HTTP-сервера: offline-эмуляция Playwright отклоняет даже локальный ответ Service Worker (microsoft/playwright#42775). Chromium проверяется с browserContext.setOffline. Оба сценария требуют ответ 200 из Service Worker и отсутствие открытого личного плана при недоступной сети. Рабочий сервис не останавливается.

## Скрытие финансовых сумм

Кнопка с глазом в заголовке рядом с аккаунтом и выходом скрывает суммы во всех разделах.
Суммы заменяются четырьмя точками, проценты накоплений и график скрываются; повторное нажатие возвращает их.
В режиме скрытия денежные поля в диалогах отображаются как password-поля с цифровой клавиатурой.
Даты, названия и навигация остаются читаемыми. План, расчёты и файлы экспорта не изменяются.
На устройстве в localStorage сохраняется только флаг вида для конкретного логина, без финансовых значений.
Состояние загружается до отображения плана, сохраняется после обновления страницы и отделено от других аккаунтов.
Это режим отображения; он не меняет авторизацию и не шифрует данные, уже загруженные в браузер.
